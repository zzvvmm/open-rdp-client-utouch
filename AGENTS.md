# Repository collaboration rules

## Branch and commit suggestions

- When completing meaningful implementation, bug-fix, documentation, or release
  preparation work that leaves changes to commit, include a suggested branch
  name and commit message in the final response when useful.
- Provide both whenever the user asks for naming suggestions.
- Base the names on the actual change and its main purpose. Keep unrelated
  changes in separate suggested commits when that makes review clearer.
- Use short, lowercase, hyphen-separated branch names with a suitable prefix:
  `feat/`, `fix/`, `docs/`, `chore/`, or `release/`.
- Use Conventional Commit messages, such as `feat(updates): add update checks`
  or `fix(input): prevent the keyboard from reopening`.
- Clearly label suggestions. Only report branches or commits as created when
  they have actually been created.
- Omit unsolicited naming suggestions for questions, status-only responses,
  or completed work with no changes left to commit.
